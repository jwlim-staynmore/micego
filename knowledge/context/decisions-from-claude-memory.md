## 사업 주체·브랜드

- 이 프로젝트는 STAYNMORE가 아니라 **MatchGo(매치고)** 기반이다. 약관·정책의 계약 당사자·개인정보처리자도 **매치고 단독**(트래블멤버스·스테이앤모어 제외).
- 서비스명은 **MICEGO(마이스고)**, MatchGo와 별도 브랜드. MatchGo 로고·Lime/Electric Blue는 쓰지 않고, 구조(White + Ink, Archivo/Pretendard/JetBrains Mono, 각진 라운드, 섹션 번호 톤)만 계승. 액센트 Teal `#0B8F86`, 하이라이트 Amber `#FFC24B`, Navy `#0F1E3D`.
- 1차 타깃은 여행사·랜드사·기업체 3개 세그먼트 균등.

## 사업 기획안 (2026-09-25)

- 1차 독자는 내부 경영진·실행팀. 목적은 경영진 승인(예산·인력·Go/No-Go)과 실행 로드맵.
- 수익 모델: 호텔 성사 커미션이 1안(기본), 추가 수익모델은 제안으로 병기.
- 기획안에서 STAYNMORE(Travelmembers)는 완전히 배제 — 호텔 네트워크·인력·계약 주체·매출 귀속 모두 MatchGo 기준(v1.1).
- 호텔 커미션 정산 시점은 체크아웃 후 30일(15일로 바꿨다가 되돌림).

## 지역 운영 파트너 모델 (2026-09-25 기획, 09-27 구현)

- 초기 호텔 공급을 빠르게 확보하려고 지역별 사업 기반이 있는 파트너사(DMC)에 **지역 운영 전체**(호텔 소싱·협상·견적 수집·확정·정산)를 위임하고 수익을 나눈다.
- 정산 흐름 A안: 파트너가 호텔에서 커미션을 수금한 뒤 MICEGO 몫을 송금. 배분 **파트너 70 : MICEGO 30**.
- 파트너 제안서는 한국어, 70:30·정산 방식까지 공개.
- 첫 후보 **Tmthai**(태국 DMC·랜드사, 한국인 담당자, 태국 전역 — 방콕·파타야·푸껫·끄라비·사무이).
- 발행본: 모델 기획안 v1.0 https://claude.ai/artifact/V42LwLd12kVbYupL3L7B6b · 파트너 제안서 https://claude.ai/artifact/8oaG48B85WBxnPQ61B4ihh · Tmthai 제휴 안내서 https://claude.ai/artifact/2cW7sEx3ZpiY8Wim4AoLeX (사본 `knowledge/artifacts/`)
- 콘솔 권한(2026-09-27): 파트너가 **같은 운영 콘솔을 직접 사용**. 권한 범위 **B** — 접수 뒤 지역이 정해지면 해당 RFP를 파트너가 요건 확인·초대·비교표 전달·선정 연결·정산까지 끝까지 운영, 본사(매치고)는 전 지역 모니터링·개입. 호텔 견적 **대리 입력 A** — 허용하되 호텔이 1회용 확인 링크로 확정해야 비교표에 실림. 비교표 전달 전 본사 호텔 검토 게이트는 **두지 않음(B, 사후 통제만)**.
- 운영자·파트너 계정 발급은 **콘솔에서 운영자가 이메일 초대**(Supabase 대시보드 수동 생성·자가 가입+승인 미채택).
- 요청이 파트너에게 맡겨지면 오거나이저에게 **고지**: 접수 확인·비딩 시작 메일 블록과 진행 상황 화면에 파트너 이름, 약관·방침에 처리 위탁·국외 이전(법무 검토 표시).
- 개인정보처리방침 제8조의 파트너 이전 국가는 서비스 대상 국가 전체(태국·베트남·인도네시아·말레이시아·필리핀·싱가포르·일본·대만·홍콩·마카오·괌·사이판·미국)를 미리 나열(B), 실제 파트너 국가(현재 태국) 병기.

## 사이트 구성

- 모바일·PC 반응형. **여행사 모드 = 한국어(`ko/`), 호텔 모드 = 영어(`en/`)**. 홈(`index.html`)은 언어 토글이 아니라 '여행사 / Hotels' 모드 선택 화면.
- 회원가입은 여행사(오거나이저)만 — 이메일 + 휴대전화(SMS) 인증. 호텔은 로그인 없는 토큰 링크. 비회원 견적 요청도 유지(가입은 권유).
- 요청(RFP)은 개인 소유 + 요청별 보기 전용 공유 링크(동료용).
- 제안 선정(성사) 시 등록 휴대전화 인증번호 확인 필수(회원·비회원 공통).
- 사이트 가격 카피는 "수수료 없음·커미션율 비공개". 초기 시안의 '이용료 0원·10% 커미션' 문구는 미채택(D-32).
- 확정 운영 정책(2026-08-10, 공개됨): ① 오거나이저 수수료 없음 ② 해외 호텔만(국내 행사 미지원, 해외면 국가·도시 제한 없음) ③ 영업일 3일 이내 회신 ④ 회사명·예산은 호텔에 비공개 ⑤ 최소 규모 제한 없음 ⑥ 시작일이 확정돼야 요청 가능(종료일 선택).
- "컨셉 검증·사전등록·베타·준비 중" 같은 표현은 다시 쓰지 않는다.
- JS가 실행되지 않는 환경(iOS Quick Look, 일부 인앱 브라우저)에서도 핵심 콘텐츠가 보여야 한다 — 진입 애니메이션은 스크립트가 부모에 `js-anim` 클래스를 붙인 뒤에만 숨김 + 2.5초 세이프티넷.
- chip-radio 그룹을 추가할 때는 클릭 핸들러가 `input.closest('.chip-radio-group')`로 스코프돼 있는지 확인.
- 화면 톤 구분: 거래 실행 화면(요청 상세·비딩 폼·이메일)은 히어로 없는 고밀도 문서 톤, 가입 유도 화면(파트너 등록 랜딩)은 마케팅 랜딩 톤.

## 상태 관리·운영

- 백엔드를 갖춘 운영자 어드민 포털을 새로 구축(Notion/시트 수동 운영·사이트 통합·설계 문서만 안은 미채택). 백엔드는 Supabase.
- 호텔은 로그인 없이 이메일 링크(토큰)로 비딩 폼 제출(호텔 로그인 포털 미채택).
- 운영 SOP v2(상태전이 시스템 기준)가 v1(mailto 기반 docx)을 대체. v2.1 확정(2026-09-26): 취합중 견적 0건·2라운드 이상이면 미성사 종료 허용, SLA 임박 = 다음 영업일 18:00 이내 또는 24시간, 오픈 도달 = SLA 충족(이후 '초대 기한'), USD 참고는 제출 금액 그대로 환산, 호텔 링크에서 선정·미선정 결과 표시, 초대별 마감 저장·재초대, 선정 후 연결 메일 자동 발송. (사본 `knowledge/artifacts/ops-sop-v2.md`)
- 피드백·VOC 창구(2026-09-27): 전 페이지 공통 버튼, 수집은 Supabase 테이블 + Edge Function 이메일(B안). 답변은 운영자가 메일함에서 직접 회신, 콘솔은 상태·메모만.
