## Hard rules
1. Every `use_figma` script MUST begin with the exact full contents of `docs/figma-v2/prelude.min.js` (one line, ~17k chars), then your code. Start with `const H = await MG('<your exact page name>');` — MG creates the page if missing and switches to it. Never touch other pages. Never delete nodes you did not create.
2. Script limit 50,000 chars → build about 3–6 frames per call. Retry-safe: if a call fails with safeToRetryWithoutCanvasRead=false, inspect the section (get_screenshot or a read-only use_figma listing children names) and only build what's missing.
3. One Figma Section per screen ID (e.g. `ORG-02 진행 상황 화면`), created with `H.section(name)`; frames are added left→right automatically (`H.frame(sec, name, kind)` with kind 'PC' | '컴팩트' | '모바일' | '모달'). Re-calling H.section with the same name returns the existing section; new frames go to the right of existing content. Call `H.finish(sec)` at the end of each script (resizes section) and return ids/counts.
4. Per frame: build the screen content with prelude atoms (siteHeader, reqBar, content, h, p, panel, progress, field, check, btn, link, table, card, kv, stateChip, shell for console, modalBody/modalFoot for modals, footer). Then annotations: `H.badge(sec, slot, '<ID · slug · 상태 이름>', '<태그>')`, `H.sticker(sec, slot, '상태 S-XXX (n)', [[slug,label],...], currentSlug, '들어오는 때: … \n할 수 있는 일: …')`, `H.note(sec, slot, buttonNode, '「버튼」 → 이동 방식 · 목적지 ID · 서버 호출', {notif:'ORG_WON', perm:['운영자'], tag:['다음 단계','…']})`, `H.marker(sec, node, '서버'|'예시 값'|'빌드 고정', 'label')`, `H.eSticker(sec, slot, 'E-34', 'one line', node?)`, `H.info(sec, slot, text, 'info'|'decide'|'check')`, `H.watermark(sec, slot)` for example-data frames, `H.ref(sec, slot, 'source')`. Keep a reference to button/link nodes you create so notes can point at them. Annotation column stacks automatically below the sticker.
