이 묶음의 모든 화면은 〔다음 단계〕입니다. 상태는 코드에서 세어 확인했고, 확인하지 못한 곳만 (추정)으로 적었습니다. 새 미결은 E-70~E-89입니다.

## 1. 공유 링크로 연 진행 상황 화면

> **왜 다음 단계인가** 공유 링크는 회원만 만들 수 있습니다(D-46). 회원제가 열리기 전에는 만들 사람이 없어서 검증에 필요하지 않습니다.

### ORG-02s 진행 상황 화면 · 공유 링크로 열었을 때 `ko/track.html?s=` 〔다음 단계〕
(화면 코드는 `data-view="share"`입니다.)

**왜 필요한가** 요청자가 동료에게 진행 상황과 비교표를 보여 주되, 선택·취소·조건 변경은 못 하게 하려고 있습니다.
**진입** 회원이 ORG-06 또는 ORG-02의 「동료와 공유」에서 링크를 만들고 메일·메신저로 전달합니다. 동료가 링크를 누르면 **페이지 이동**으로 열립니다. 로그인은 필요 없습니다. 주소에 `?s=`가 있고 `?t=`가 없으면 공유 화면이 됩니다.
**데이터** 서버(`get_track`, `{share}`)가 `view:"share"`, `caller_is_owner:false`로 답합니다. 응답에서 `can_cancel`, `pick`, `share`가 빠집니다.

① 화면 상태 (12개, 요청자 화면과 같은 목록)

| 상태(slug) | 공유 화면에서 보이는 것 | 요청자 화면과 다른 점 |
|---|---|---|
| loading | 「불러오는 중입니다… / Loading…」 | 같음 |
| received 접수됨 | 접수 안내 | 「조건 변경 메일」 문장과 「요청 취소」 버튼이 없음 |
| verifying 요건 확인 중 | 확인 중 안내, 회신 기한 | 위와 같음 |
| rejected 진행 불가 | 반려 안내와 사유 글 | 사유 글(`reason.text`)이 공유자에게도 보임 → E-79 |
| bidding 호텔 제안 받는 중 | 진행 단계, 호텔 곳수, 마감 | 「동료와 공유」 패널, 「질문 보내기」가 없음 |
| rebid 새 조건으로 재요청 | 라운드 2 이상 안내, 바뀐 내용(`change_summary`) | 위와 같음 |
| collecting 제안 정리 중 | 정리 중 안내 | 위와 같음 |
| delivered 비교표 도착 | 비교표(제안 A·B·C, 정렬·카드/표 전환) | 「제안 선택하기」, 「궁금한 점이 있나요?」 패널이 없음. 호텔명은 가려진 채 |
| won 연결 완료 | 선정 제안과 호텔명, 연결 일시 | 선택 인증 영역이 없음 |
| lost 종료 | 미성사 안내 | 「새로 요청하기」 버튼은 그대로 남음 → E-79 |
| cancelled 취소됨 | 취소 안내 | 위와 같음 |
| invalid 링크를 열 수 없음 | 「링크를 열 수 없습니다」, 「문의하기」, 「이메일 보내기」 | 링크 오타·회수·만료·탈퇴를 구분하지 않음 → E-79 |

모든 상태 위에 「보기 전용 공유 링크입니다. 요청하신 분이 공유했습니다. 제안 선택과 조건 변경은 요청하신 분만 할 수 있습니다.」 배너가 붙습니다. 「← 내 견적 요청」 링크와 「이 링크는 요청하신 분 전용입니다」 안내는 `.owner-only`라서 DOM에서 지워집니다.
유효 기간: 요청이 끝나고 30일 뒤 시스템이 `expired`로 바꿉니다(`system_tick`). 회원이 끄거나 새 링크를 만들면 `revoked`, 회원이 탈퇴하면 `disabled`입니다. 세 경우 모두 화면은 invalid입니다 → 6-4.

주요 버튼

| 버튼 | 누르면 |
|---|---|
| 「USD 참고 낮은 순」「도착 순」, 「카드」「표」 | 인라인 패널: 같은 화면에서 비교표 정렬·보기 방식만 바뀜 |
| 「새로 요청하기」 (lost·cancelled·rejected) | 페이지 이동 → `index.html#register` |
| 「문의하기」 (invalid) | 페이지 이동 → `contact.html` |
| 「이메일 보내기」 (invalid) | 외부 앱: 메일 앱이 `[MICEGO 링크 문의]` 제목으로 열림 |

⑤ 미결 → **E-79**. 열람 횟수는 서버가 세어 ADM-07 「공유 링크」 표의 「열람」 칸에 보여 줍니다.

## 2. 회원제 화면 (ORG-03 ~ ORG-08)

> **왜 다음 단계인가** 견적 요청은 회원가입 없이 됩니다. 회원제는 요청을 한곳에 모으고 공유 링크를 만드는 편의 기능이라, 두 흐름 검증이 끝난 뒤에 열어도 됩니다.

회원 상태는 `pending_email` → `pending_phone` → `active` ⇄ `locked`/`suspended`, `active` → `withdrawn`입니다(ADM-06 표 참고). 가입을 끝내지 않은 계정은 72시간 뒤 자동으로 파기됩니다.
화면 문구에서 요청자를 부를 때는 「주최 측」·「님」을 씁니다.

### ORG-03 회원가입 `ko/signup.html` 〔다음 단계〕
**왜 필요한가** 이메일과 휴대전화를 인증한 계정을 만들어, 같은 이메일로 접수한 이전 견적 요청을 자동으로 연결합니다.
**진입** `index.html` 헤더·ORG-04의 「회원가입」·ORG-02의 가입 안내에서 **페이지 이동**. `?email=`이 있으면 이메일 칸이 채워집니다(ORG-04가 인증 전 계정을 되돌려 보낼 때). 견적 요청 접수 완료 화면의 안내 상자도 이 화면으로 옵니다.
**서버 호출 순서** `signup_start` → `verify_email` (재발송 `resend_email_code`) → `send_phone_otp(signup_phone)` → `verify_phone_otp` → 화면이 `login`을 불러 로그인.

① 화면 상태 (12개)

| 상태(slug) | 화면 이름 | 언제 들어오나 | 보이는 것 | 할 수 있는 일 |
|---|---|---|---|---|

규칙(→ 6-4): 이메일 코드 10분·5회·재발송 60초 간격·하루 10회, 휴대전화 코드 3분·5회·재발송 60초 간격·하루 5회. 비밀번호는 10자 이상이고, 영문·숫자·특수문자 중 2종 이상이거나 12자 이상이며, 이메일 앞부분(3자 이상)을 넣지 않습니다. 이미 가입된 이메일로 시작해도 화면은 똑같이 email_sent로 가고, 실제로는 「ACC_EMAIL_EXISTS」 메일만 나갑니다(계정 존재 여부를 숨기려는 설계). 같은 메일이 시간당 1통을 넘으면 조용히 건너뜁니다. Turnstile은 이 화면에서 켜지면 `signup_start`에 붙습니다(D-50, 시크릿이 없으면 꺼짐).

### ORG-04 로그인 `ko/login.html` 〔다음 단계〕

### ORG-05 비밀번호 재설정 `ko/reset.html` 〔다음 단계〕
**왜 필요한가** 비밀번호를 잊거나 잠긴 계정을 푸는 유일한 셀프 경로입니다. 이메일로만 합니다.
**진입** ORG-04의 링크, 또는 재설정 메일(ACC_PW_RESET)의 링크 `reset.html?k=…`. **페이지 이동**(메일은 외부 앱에서 열림). 링크는 30분, 1회용입니다.

**BRIEF·다른 문서와 어긋난 곳**
1. **초대 상태 `hotel_confirmed`**: BRIEF 초대 상태 표는 "호텔 확인 완료"를 따로 둠. 코드(`quote_confirm_apply`)는 확인하면 초대를 곧바로 `submitted`로 바꾸고 확인 사실은 `quotes.confirmed_at/confirmed_via`에 남김. `hotel_confirmed`는 비교표 조회 쿼리에 이름만 남아 있고 현재 어떤 경로도 이 값을 쓰지 않음. 이 묶음은 코드를 따랐습니다. 통합 때 BRIEF 표를 고칠지 정해 주세요.
