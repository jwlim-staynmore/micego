## 0. 읽는 법

### 0-1. 이 문서를 쓰는 순서
1. 1장 공통 규칙을 먼저 읽고 Figma 페이지마다 같은 방식으로 적용합니다.
2. 2장을 페이지 번호 순서로 따라 합니다. 표 한 줄이 프레임 하나입니다.
3. 3장의 작업 순서대로 진행하고, 끝나면 완료 확인 체크리스트를 채웁니다.

### 0-2. 무엇을 그리는가
- 프레임은 **현재 코드가 하는 동작**을 그립니다. 코드가 진실입니다(v2 0장).
- 코드의 결함은 프레임 옆에 E-번호 스티커로만 붙입니다. 고친 모습은 06 개선 보드에만 그립니다.
- 요청자 화면 안의 배지·문구는 바꾸지 않습니다. 요청자에게 보이는 말은 v2 3-3 표의 「요청자 화면 배지」 열 그대로입니다(「호텔 제안 받는 중」, 「제안 정리 중」, 「비교표 도착」, 「연결 완료」 등). 새 상태 이름은 운영 콘솔과 설명 글에만 씁니다.
- 호텔 화면(HTL-*)의 화면 문구는 영어 그대로 둡니다.
- 〔다음 단계〕 화면은 상태마다 그리지 않고 회색 요약 프레임 한 장으로 끝냅니다.

### 0-3. 표를 읽는 규칙 (스크립트도 같은 규칙으로 읽습니다)
| 약속 | 뜻 |
|---|---|
| 표 한 줄 = 프레임 한 개 | `{PC,모바일}`이면 PC(1280px)와 모바일(360px) 두 프레임, `{PC}`면 PC만. 이름 끝에 ` · PC` / ` · 모바일`을 붙여 만듭니다 |
| 칸 안의 `<br>` | 줄바꿈입니다 |
| 칸 안의 `;` | 항목 구분입니다. 분기 노트는 항목 하나가 노트 하나입니다 |
| 칸 안에는 세로선 문자를 쓰지 않습니다 | 표가 깨지지 않게 하려는 약속입니다 |
| 세트 `S-…` | 1-3의 상태 스티커 세트 이름입니다. 스티커 본문은 세트를 펼쳐서 만들고, 줄의 「현재」 상태만 강조합니다 |
| 「…」 | 화면에 보이는 문구를 그대로 옮긴 것입니다 |
| 표 머리줄 | 02·03·04 페이지 표는 모두 같은 일곱 칸입니다: 프레임 이름 · 배지 텍스트 · 태그 · 상태 스티커 본문 · 분기 노트 · 데이터 출처 표시 · v2 근거 절 |

### 0-4. 그림이 아닌 것
- 경쟁사 화면 캡처를 넣지 않습니다.
- 이름 없는 레이어를 남기지 않습니다(`Frame 123`, `Rectangle 4` 금지).
- 예시 데이터를 담은 프레임은 반투명 워터마크 「예시」를 겹칩니다(1-6).

## 1. 공통 규칙

### 1-1. 프레임 이름
형식은 `화면 ID · 상태 slug · 화면 이름 · PC` 또는 `· 모바일`입니다.

| 칸 | 규칙 | 보기 |
|---|---|---|
| 화면 ID | v2 부록 A와 5장의 ID 그대로 | `ORG-02` |
| 상태 slug | 코드의 영어 상태 이름. 상태가 없는 화면은 `default` | `delivered` |
| 화면 이름 | 3장 용어집의 말. 짧게 | `진행 상황 화면` |
| 기기 | `PC`(너비 1280px) 또는 `모바일`(너비 360px). 콘솔은 PC만 | `PC` |

- 한 상태가 둘로 갈리는 곳(세부 상태·오류 변형)은 slug 뒤에 `-` 와 짧은 영어 이름을 붙입니다: `delivered-p1`, `received-cancel`, `open-error`.
- 예시 이름: `ORG-02 · delivered · 진행 상황 화면 · PC`
- 같은 프레임 안 레이어도 이름을 답니다: `badge/id`, `badge/tag`, `sticker/states`, `note/branch-1`, `marker/source-server` 처럼 `역할/이름` 형식.
- 지시서 안에서만 쓰는 임시 ID: `ADM-COM`(콘솔 공통 틀), `PTR-REF`(지역 파트너 참고표). v2 본문에는 ID가 없습니다.

**기존 프레임 찾기.** 이미 있는 프레임은 이름 앞부분(`화면 ID · 상태`)으로 찾습니다. 이름이 다르면 아래 표로 옮깁니다. 못 찾으면 새로 만듭니다.

### 1-2. ID 배지와 MVP 태그
모든 프레임 왼쪽 위 모서리에 배지를 답니다. 배지는 두 조각입니다.

- 왼쪽 조각(글자): `화면 ID · 상태 slug · 상태 이름`. 예: `ORG-02 · delivered · 비교표 도착`
- 오른쪽 조각(색 칩): MVP 태그

| 태그 | 칩 글자 | 색 | 쓰는 곳 |
|---|---|---|---|
| 핵심 | 핵심 | 초록 `#1F9D55` | 〔MVP 핵심〕 화면 |
| 보조 | 보조 | 노랑 `#E0A800` | 〔보조〕 화면 |
| 다음 단계 | 다음 단계 | 회색 `#8A8F98` | 〔다음 단계〕 화면. 프레임 전체를 회색 톤으로 |
| 결정 대기 | 결정 대기 | 보라 `#7C5CDB` | G-1~G-4 때문에 범위가 안 정해진 화면·상태 |

- 한 프레임에 태그는 하나입니다.
- 한 화면 안에서 일부 요소만 다른 태그이면(예: ORG-02의 선택 인증), 그 요소 옆에 작은 칩으로 한 번 더 답니다.
- 배지 상태 이름은 화면 종류별로 다릅니다. 요청자 화면은 「요청자 화면 배지」 열, 운영 콘솔은 「표준 이름」 열, 호텔 화면은 영어 배지(`Open for quotes` 등)를 씁니다.

### 1-4. 분기 노트
- 버튼 옆 말풍선(노란 메모 모양)에 한 줄로 씁니다. 이름은 `note/branch-n`.
- 형식: **「버튼 문구」 → 이동 방식 · 목적지 ID · 서버 호출**
- 이동 방식은 네 가지만 씁니다: **페이지 이동** / **모달** / **인라인 패널** / **외부 앱**. 화면 안 앵커 이동은 「페이지 이동(같은 화면 `#anchor`)」으로 적습니다.
- 서버 호출이 없으면 「서버 호출 없음」, 서버 이름이 아직 정해지지 않은 곳은 「(추정)」을 붙입니다.
- 분기 노트는 노트마다 선(커넥터)으로 버튼에 연결하고, 목적지가 다른 화면이면 그 화면 프레임까지 선을 이어 줍니다(같은 페이지 안에 있을 때).

### 1-5. 데이터 출처 표시
프레임 안 영역마다 오른쪽 위에 작은 표식을 붙입니다. 이름은 `marker/source-…`.

| 표식 | 글자 | 색 | 뜻 |
|---|---|---|---|
| 서버 | 서버 | 파랑 `#2F6FDE` | 서버 응답으로 채우는 값 |
| 빌드 고정 | 빌드 고정 | 진회색 `#4A4F57` | 빌드 때 HTML에 박힌 문구·선택지 |
| 예시 값 | 예시 값 | 주황 `#E8710A` | 서버가 값을 줘도 화면이 읽지 않고 빌드 때 넣은 예시가 남는 곳(E-1 계열) |

표식 색은 지시서가 새로 정했습니다(v2 본문에는 색 규정이 없습니다). 바꾸고 싶으면 이 표만 고치면 됩니다.

### 1-6. 금지 · 워터마크
- 경쟁사 화면 캡처 금지.
- 이름 없는 레이어 금지.
- **「예시」 워터마크**: 가짜 호텔명·가짜 REF·가짜 일정·가짜 비교표처럼 예시 데이터가 들어간 프레임에 겹칩니다. 큰 회색 글씨, 불투명도 12%, 대각선 -20도, 레이어 이름 `watermark/example`. 요청자 화면(ORG-02), 호텔 견적 페이지(HTL-03), HTL-02, 데모 미리보기 프레임이 해당됩니다.
- 실제 개인 정보처럼 보이는 값 금지. 휴대전화는 `010-****-5678` 같은 가린 모양만 씁니다.
- 호텔 화면에는 요청자 신원(회사명·담당자·연락처·예산)을 그리지 않습니다. 단 `selected` 프레임의 「Organizer contact」 카드는 예시 값으로 채우고 워터마크를 겹칩니다.

### 2-1. 페이지 `01 사용자 플로우`

역할별 흐름 4종을 한 줄씩 가로로 놓습니다(위에서부터 요청자 · 호텔 · 운영자 · 지역 파트너). 규칙은 아래와 같습니다.

- 노드 하나가 화면 하나입니다. 노드 글자는 **화면 ID + 화면 이름**(예: `ORG-02 진행 상황 화면`). 노드 위에 태그 색 점을 찍습니다. 알림은 종 모양 노드, 끝 상태는 둥근 모서리 노드로 그립니다.

#### 2-4-3. ADM-03 견적 요청 상세 (핵심 중 핵심)

공통 규칙
- 머리줄(`MG-2610-014` + 상태 칩 + 「라운드 n」, SLA 배지, 「진행 상황 링크 복사」(옛 「추적 링크 복사」), 「목록으로」)과 상태 전이 카드는 모든 상태 프레임에 같은 위치에 그립니다.
- 상태 전이 카드는 안내 문구 → 전이 버튼 → 가드 힌트(버튼 아래 빨간 한 줄) 순서입니다. 버튼이 없으면 「이 상태에서는 바꿀 수 있는 항목이 없습니다.」
- 「반려」 「요청 취소」 버튼은 빨간 버튼입니다.
- 모든 전이 버튼의 분기 노트는 형식 「버튼 → 이동 방식 · 목적지 · `admin_transition(p_ref, p_action, p_reason, p_note, p_memo, p_consent)`」입니다. 이동 방식은 모달을 거치면 「모달」, 거치지 않으면 「인라인 패널(같은 화면의 상태 카드가 바뀜)」입니다.
- 카드 이름은 새 이름으로: 「요청 내용」 · 「요청자 정보」(배지 「호텔에 보이지 않음」) · 「소유 · 공유 · 선택 인증」(운영자만) · 「익명화 검토」 · 「마감 · 초대」 · 「초대 현황」 · 「비교표」 · 「이전 라운드」 · 「이력」.

### 2-5. 페이지 `05 화면별 동작 노트`

화면 ID마다 노트 카드 한 장을 만듭니다. 이름은 `note/화면 ID`. 카드는 v2 5장의 같은 화면 설명 안에 있는 **① 화면 상태 → ② 요소 → ③ 상태 전환** 소제목을 같은 순서로 따라갑니다. 맨 위에 「왜 필요한가」 한 줄과 「누가 · 어떻게 들어오나」 한 줄을 붙이고, 맨 아래에 **v2 링크 줄**을 둡니다.

**카드 모양**
1. 제목: `화면 ID 화면 이름` + 태그 칩 (1-2).
2. 한 줄 요약 두 개: 왜 필요한가 / 누가·어떻게 들어오나.
3. ① 화면 상태: 상태 slug · 화면 이름 · 언제 들어오나 3열 표.
4. ② 요소: 버튼마다 한 줄 `「문구」 → 이동 방식 → 결과` (기본·비활성·진행 중·완료·오류 다섯 상태는 v2 표를 따라 한 줄 뒤에 괄호로 요약).
5. ③ 상태 전환: `지금 → 다음 · 누가·조건 · 알림 · 서버 호출`.
6. v2 링크 줄: 「명세서 v2 › 5장 {A·B·C·D} › {화면 ID} {화면 이름}」 + 파일 경로. 링크는 저장소 안 파일을 가리키는 글이므로, 사람이 열 때는 파일을 열고 화면 ID로 문서 안에서 찾습니다.

④ 숨김·보안과 ⑤ 미결은 카드에 쓰지 않고, ④는 해당 프레임의 「이 화면에 절대 나오면 안 되는 정보」 메모로, ⑤는 06 개선 보드로 보냅니다. 카드 하단에 `→ 06` 칩으로 E-번호만 적습니다.

핵심 화면은 표를 통째로 옮기고, 보조·다음 단계는 ①과 ③만 짧게 옮깁니다.
