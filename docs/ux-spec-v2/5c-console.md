## C. 운영 콘솔 (운영자 화면)

기준은 코드입니다. 코드: `admin/index.html` · `dashboard.html` · `rfps.html` · `rfp.html` · `partners.html` · `partner.html` · `settings.html`, 공용 `admin/admin.js` · `partner.js` · `data-adapter.js`, 서버 `supabase/migrations/0003·0005·0012·0013·0017·0019`. 상태 전이 규칙은 `docs/state-transitions.html` v1.9의 #0~#12 번호를 따릅니다.

- 이 장의 상태 이름과 버튼 문구는 BRIEF §2의 새 이름이고, 이 브랜치의 콘솔 코드(`admin.js` `STATES`·`INV`·`BTN`·`HINTS`·`A.FILTERS`)도 같은 이름으로 바뀌었습니다. 메뉴 이름(「견적 관리」 「호텔 파트너」)과 몇몇 문구(「추적 링크 복사」 「승인 파트너」 「견적 상세」 「파트너 상세」)는 아직 옛 말이라 화면 문구 그대로 「」 안에 적습니다. 남은 목록은 끝의 「C 묶음 작성 메모」에 있습니다.
- 운영자가 쓰는 화면입니다. 지역 파트너(partner_org)가 같은 화면에서 다르게 보이는 곳은 〔다음 단계〕로 짧게만 적습니다.
- 모든 화면은 JavaScript가 있어야 보입니다(`<noscript>` 안내만 나옴). 요청자·호텔 화면과 달리 JS 꺼짐 대응이 없습니다 → 6-2.

### 콘솔 공통

콘솔 모든 화면(ADM-00 제외)이 `A.boot(...)`로 같은 틀을 그립니다. 아래는 화면마다 다시 쓰지 않습니다.

| 항목 | 동작 | 코드 근거 |
|---|---|---|
| 틀 | 왼쪽 메뉴(PC) / 위쪽 「메뉴」 펼침(모바일), 위쪽 줄에 「{역할} · {이메일}」과 「로그아웃」 버튼, 본문 `main`, 토스트 영역 | `A.boot` |
| 메뉴 | 「대시보드」 「견적 관리」 「호텔 파트너」 「정산」 「회원」 「지역 파트너」 「피드백」 「설정」(운영자). 「견적 관리」는 견적 요청 목록, 「호텔 파트너」는 호텔 목록입니다. 지역 파트너 계정은 회원·지역 파트너·피드백·설정이 빠지고 「내 조직」이 생김 | `NAV_ALL` |
| 메뉴 배지 | 「호텔 파트너」 옆 「심사 지연 n건」 · 회원 「연결 요청 대기 n건」 · 피드백 「새 접수 n건」 · 정산 「정산 처리 필요 n건」 · 대시보드 「개입 필요 n건」(운영자) | `A.boot`, `A.refreshBadge` |
| 토스트 | 화면 오른쪽 아래, **6초** 뒤 사라짐. 종류 3가지: 성공(ok) · 오류(error) · 안내(info). `role=status`, `aria-live=polite`. 닫기 버튼 없음 | `A.toast` |
| 모달 | 브라우저 `<dialog>.showModal()`. 「취소」 버튼과 Esc는 둘 다 취소(결과 없음). 확인을 누르면 입력을 검사하고, 틀리면 모달 안 빨간 줄(`dlg-err`)에 문구를 보이며 닫지 않음. 열릴 때 첫 입력칸에 포커스 | `dialog` |
| 확인 모달 | 제목 「확인」, 본문 한 문단, 버튼 「취소」/지정 문구 | `A.confirm` |
| 모드 | `MG_CONFIG.supabase.url`이 있고 `MG.mode==='api'`이면 api 모드, 아니면 mock 모드 | `data-adapter.js` |
| mock 모드 | 화면 맨 위에 리본 「DEMO · 예시 데이터 · 새로고침하면 처음 상태로 돌아갑니다」+ 「예시 데이터 초기화」 링크. 시계는 **2026-10-08(목) 19:30 KST 고정**. 서버 호출 없음 | `mock-data.js`, `MGA.now` |
| 지역 파트너 시연 | mock 모드에서 주소에 `?as=partner`를 붙이면 파트너 관리자(티엠타이) 화면으로 바뀌고 `sessionStorage.micego_demo_as`에 남음. `?as=operator`로 되돌림. 역할이 바뀌면 예시 데이터를 새로 시작 〔다음 단계〕 | `MGA.boot`, `load` |
| api 모드 | 페이지를 열 때 세션·역할을 확인(없으면 `index.html`, 역할이 맞지 않으면 `index.html?e=role`)하고 `admin_snapshot()` 한 번으로 전체 데이터를 받음. 실패하면 `index.html?e=snapshot` | `MGA.boot` |
| 저장 `A.persist(op, args, localFn)` | mock: `localFn`을 실행하고 `sessionStorage`(`micego_admin_state_v1`)에 저장. api: RPC를 부르고, 응답이 요청 전체이면 그 항목을 통째로 바꿈. 응답이 확인(ack)뿐이면 `localFn`을 같이 실행. 끝나면 `A.onChange()`가 화면을 다시 그림 | `A.persist`, `replaceEntity` |
| 오류 문구 | 서버 오류 `MG:코드`를 `CM_ERR` 표로 바꿈. 표에 있는 코드는 4개뿐(아래). 나머지는 서버 메시지를 그대로 토스트(오류)로 보임. 서버에 닿지 못하면 「네트워크 오류가 발생했습니다」 → E-50 | `CM_ERR`, `rpcError` |
| 불러오는 중 | 전용 표시가 없습니다. api 모드에서 `admin_snapshot()`을 받는 동안 본문이 비어 있습니다 → E-90 | `A.boot`, `load` |
| 화면 시각 | 페이지를 연 시점의 시각 하나(`A.NOW`)를 계속 씀. 열어 둔 채로는 SLA 배지가 바뀌지 않음 → E-66 | `A.boot` |
| 동시 수정 | 화면은 `row_version`을 보내지 않음. 두 사람이 같은 견적 요청을 고치면 나중 저장이 이김 (추정) → E-67 | `persist` 인자 |

`CM_ERR`에 있는 4개 코드와 문구:

| 서버 코드 | 토스트 문구 |
|---|---|
| COMMISSION_NOT_AGREED | 요율에 동의한 호텔이 없어 초대할 수 없습니다. 호텔이 동의 링크를 누른 뒤에 초대해 주세요. |
| COMMISSION_OUT_OF_RANGE | 허용 범위를 벗어난 요율입니다. 범위 밖 요율은 본사에 요청해 주세요. |
| COMMISSION_RATE_REQUIRED | 승인하려면 커미션 요율을 입력해 주세요. |
| GUARD_CONSENT | 동의 확인 방법·일시·근거(10자 이상)를 모두 입력해 주세요. |

### ADM-00 콘솔 로그인 `admin/index.html` 〔MVP 핵심〕

**왜 필요한가** 운영자와 지역 파트너만 콘솔에 들어오게 합니다. 운영자가 없으면 접수된 견적 요청을 처리할 수 없습니다.
**누가 · 어떻게 들어오나** 운영자가 콘솔 주소를 직접 입력하거나, 세션이 없는 상태에서 다른 콘솔 화면을 열면 이 화면으로 돌아옵니다(페이지 이동). 오류로 돌아올 때는 주소에 `?e=role` · `?e=config` · `?e=snapshot`이 붙습니다.
**나가는 길** 「로그인」 성공 → ADM-01 대시보드 (페이지 이동). 계정 만들기·비밀번호 찾기 링크는 없습니다.
**데이터** api 모드는 Supabase Auth `signInWithPassword`로 확인하고 `app_metadata.role`이 operator · partner_admin · partner_member 중 하나여야 통과합니다. mock 모드는 이메일·비밀번호가 비어 있지만 않으면 통과하고 `sessionStorage.micego_admin_role='operator'`만 저장합니다(실제 인증 없음).
**Figma** `ADM-00 · 기본` · `ADM-00 · 입력 오류` · `ADM-00 · 로그인 실패` | **코드 근거** `admin/index.html` 인라인 스크립트, `MGA.login`, `MGA.logout`

### ADM-03 견적 요청 상세 `admin/rfp.html?id=` 〔MVP 핵심〕

**왜 필요한가** 한 견적 요청의 모든 작업이 여기서 일어납니다. 상태 전이, 요건서 익명화, 마감과 초대, 비교표 정리, 선정 표시, 성사 닫기를 합니다. 검증의 두 흐름이 이 화면 없이는 끝까지 돌지 않습니다.
**누가 · 어떻게 들어오나** ADM-01·02의 번호 클릭(페이지 이동). 주소의 `id`가 없거나 틀리면 「해당 견적을 찾을 수 없습니다」+ 「견적 관리로 돌아가기」.
**나가는 길** 「← 견적 관리」 · 「목록으로」 → ADM-02 (페이지 이동) / 소유자 이름 → 회원 상세 (페이지 이동, 이 묶음 밖) / 「필요하면 직접 다시 보내기」 → 메일 앱 (외부 앱) / 「팔로업 메일」 → 메일 앱 (외부 앱).
**데이터** 서버 응답: `admin_snapshot()`의 `rfps[]`(요청 내용 · 요청자 정보 · 초대 · 견적 · 이력 · 토큰 · 선택 인증 기록). 전이·초대·표시 저장 뒤에는 서버가 돌려준 요청 전체로 바꿉니다. 승인 호텔 후보는 `partners[]`.
**Figma** `ADM-03 · 접수됨` · `· 요건 확인 중` · `· 초대 준비` · `· 견적 받는 중` · `· 견적 정리 중` · `· 비교표 전달됨` · `· 성사` · `· 미성사` · `· 반려` · `· 취소됨` (+ 모달: `반려/미성사/취소 사유` · `조건 변경` · `동의 확인 기록` · `초대 2곳 미만 확인` · `마감 변경 확인`) | **코드 근거** `rfp.html` 섹션 함수 · 클릭 처리, `admin.js` `STATES` `INV` `BTN` `HINTS` `ALLOWED`(44~79), `A.guard`(617), `A.request`(670), 모달 함수(779~823), 서버 `admin_transition`(0019), `private.rfp_transition`(0013)

④ 숨김·보안
- 커미션 요율은 요청자에게 보이지 않습니다(D-32·D-37). 호텔 견적 페이지와 초대 메일에는 합의 요율이 한 줄 나갑니다(D-42).
- `partners` 테이블은 열 단위 읽기 권한이라 새 열을 추가하면 같은 마이그레이션에 `grant select (새컬럼) on partners to authenticated`가 있어야 이 화면에 보입니다(CLAUDE.md 5). 요율 토큰·IP 해시 열은 일부러 제외돼 있습니다.

⑤ 미결
- 커미션 카드와 요율 합의를 MVP에 둘지 → **결정 대기**(BRIEF §5 「요율 합의 조건을 MVP에서도 둘지」) → E-63.
- 호텔 상태 이름(신청 · 심사중 · 승인 · 거절 · 중지)은 BRIEF §2에 새 이름이 없어 코드 이름을 그대로 씁니다. 용어집의 「승인 호텔」 = 상태 승인.
- 체크리스트 서버 검사가 화면보다 느슨합니다 → E-59.

### 열린 항목 (E-50 ~ E-69, E-90)

**E-50 서버 오류 원문이 토스트에 그대로 나옴**
- 무엇이 문제인가: `CM_ERR`에 코드 4개뿐입니다. GUARD_ANON · GUARD_BIDDING · GUARD_NO_QUOTE · GUARD_USD · GUARD_SELECT_ONE · GUARD_LOST_COLLECTING · GUARD_REASON · STATE_CONFLICT · FORBIDDEN · VALIDATION은 `MG:GUARD_ANON`처럼 보입니다.
- 어디서: `admin.js` `A.persist`의 `CM_ERR[err.code] || err.message`, `data-adapter.js` `rpcError`.
- 영향: 화면 검사를 통과했는데 서버가 막는 경우(오래 열어 둔 화면, 동시 수정)에 운영자가 이유를 못 읽습니다.
- 제안: 코드마다 한국어 문구를 `CM_ERR`에 추가하고 알 수 없는 코드는 「처리하지 못했습니다 ({코드})」로 통일.
- 상태: 수정 가능. 다른 묶음과 문구 공유 필요(6-5).

**E-51 공개 메모를 저장하면 익명화 검토 완료가 풀리는지 mock과 서버가 다름**
- 무엇이 문제인가: mock `localFn`은 메모가 바뀌면 `anonReviewed=false`로 되돌립니다. 서버 `admin_rfp_update`는 메모만 바꾸고 완료 표시를 그대로 둡니다. api 모드는 서버 응답으로 통째로 바꾸므로 완료 표시가 남습니다.
- 영향: 메모를 고친 뒤 재검토 없이 초대 준비로 넘어가 신원이 들어간 메모가 호텔에 갈 수 있습니다.
- 제안: 서버가 `publicMemo`가 바뀌면 `anon_reviewed=false`, `anon_at=null`로 함께 바꿈. 이력에 「익명화 검토 완료 표시 해제」 기록.
- 상태: 수정 필요(신원이 호텔에 보일 위험).

**E-52 익명화 검사는 화면에서만 하고 규칙이 좁음**
- 무엇이 문제인가: 가려야 할 값을 찾는 규칙(회사명 · 담당자 이름 첫 단어 · 이메일 · 전화 · 금액 · 「예산」)이 `rfp.html`에만 있고 서버는 완료 표시만 저장합니다. 영문 이름, 약칭, 지명+회사명 조합은 못 찾습니다.
- 영향: 우회하거나 규칙 밖 표현이 호텔에 갑니다.
- 제안: 검사 규칙을 서버 함수로 옮기고 운영 중 놓친 사례를 규칙에 추가. 놓침 사고 때 OPS_ORG_ANON_INCIDENT.
- 상태: **결정 대기**(서버 이전 시점).

**E-53 선정 표시 서버 검증이 없음**
- 무엇이 문제인가: `admin_mark_selection`은 상태를 보지 않고 「선정 1곳」도 강제하지 않습니다. mock은 다른 선정을 지우지만 서버는 여러 곳을 선정으로 둘 수 있습니다. 성사 때 GUARD_SELECT_ONE이 `MG:GUARD_SELECT_ONE`으로 보입니다.
- 영향: api 모드에서 선정 표시가 둘 이상 남고 성사가 막히며 원인이 보이지 않습니다.
- 제안: 서버가 같은 요청에서 기존 선정을 해제하고 비교표 전달됨에서만 허용.
- 상태: 수정 필요.

**E-54 「호텔 n곳에 초대를 보냈습니다」 건수가 실제와 다를 수 있음**
- 무엇이 문제인가: 토스트는 체크한 호텔 수입니다. 서버는 이미 초대한 호텔, 지역 밖 호텔(지역 파트너), 합의 전 호텔을 건너뛰고 하나라도 보내면 성공으로 응답합니다. 건너뛴 호텔은 이력에만 남습니다.
- 영향: 운영자가 모두 나간 줄 알고 마감을 기다립니다.
- 제안: 서버 응답에 보낸 수와 건너뛴 이름을 담고 토스트에 「n곳 보냄 · m곳 제외(이유)」.
- 상태: 수정 필요.

**E-55 초대 준비 단계에서 초대가 즉시 나감**
- 무엇이 문제인가: `admin_invite`는 상태가 초대 준비여도 HTL_INVITE를 바로 보냅니다. 호텔은 링크를 열 수 있습니다(`state-transitions` 2장 open 행). 이름은 「초대 준비」인데 실제로는 이미 초대 중입니다. BRIEF §2의 호텔 화면 열도 이 단계에서 「안 보임」으로 돼 있습니다.
- 영향: 요청자 화면은 「요건 확인 중」인데 호텔은 이미 견적을 쓸 수 있습니다.
- 제안: (a) 초대 메일을 「견적 받기 시작」 때 한꺼번에 보내거나 (b) 이 단계 이름을 「초대 중」으로 바꿈.
- 상태: **결정 대기**.

**E-56 초대 후보를 목적지 글자 일치로 거름 (추정)**
- 무엇이 문제인가: `inviteCard`는 `p.dest===r.destination`(문자열 같음)으로 후보를 만듭니다. 서버는 지역 코드로 맞춥니다(`region_covers`). 「다낭」과 「다낭/호이안」처럼 글자가 다르면 후보에서 빠집니다. 서버 값 구성은 확인하지 못했습니다.
- 영향: 승인 호텔이 있는데 후보가 비어 보입니다(「초대할 수 있는 승인 파트너가 더 없습니다.」).
- 제안: 지역 코드 기준으로 맞추고, 지역 밖 호텔은 별도 줄로 보임.
- 상태: 확인 필요.

**E-57 지역 파트너 담당자에게 반려 · 취소 · 성사 버튼이 보임** (5장 D의 E-88과 같은 문제. 한 번만 고치면 됨)
- 무엇이 문제인가: 서버는 partner_member의 rejected · cancelled · won을 FORBIDDEN으로 막는데, `side()`는 역할을 보지 않고 버튼을 그립니다. 성사만 화면에서 미리 토스트로 막습니다.
- 영향: 반려·취소를 누르면 사유 모달까지 가고 마지막에 `MG:FORBIDDEN`이 보입니다 〔다음 단계〕.
- 제안: 담당자에게는 해당 버튼을 숨기거나 비활성 + 이유 문구.
- 상태: 수정 가능.

**E-58 USD 참고 입력 저장이 불안정**
- 무엇이 문제인가: ① 서버가 `coalesce`로 저장해 빈 값으로 지울 수 없습니다. ② 입력값을 화면에 먼저 적고 500ms 뒤에 저장하므로, 저장이 실패해도 화면에는 값이 남습니다(실패 토스트만). ③ 500ms 안에 화면을 떠나면 저장이 사라질 수 있습니다 (추정).
- 영향: 「비교표 전달」 직전에 미입력이 있다고 서버가 막는데(GUARD_USD) 화면은 모두 입력됨으로 보입니다.
- 제안: 값이 비면 지우기로 처리, 실패 시 입력칸을 이전 값으로 되돌림, 화면을 떠날 때 저장 대기분 즉시 전송.
- 상태: 수정 필요.

**E-59 호텔 승인 체크리스트가 화면(6항목)과 서버(3항목)에서 다름**
- 무엇이 문제인가: 화면은 도메인 일치(또는 소속 메모) · 해외 소재 · 단체 50명 이상까지 6항목을 모두 요구합니다. 서버는 실재 확인 · 수용 일치 · 연락처 확인 3개만 보고 모자라면 `MG:VALIDATION`을 줍니다.
- 영향: 지역 파트너나 다른 경로(RPC 직접 호출)로는 해외 소재·50명 미만 호텔도 승인됩니다.
- 제안: 서버를 화면 기준 6항목으로 맞추거나, 해외·50명은 신청 단계에서 거르고 화면 항목에서 뺌.
- 상태: **결정 대기**.

**E-60 mock 리본 문구와 실제 동작이 다름**
- 무엇이 문제인가: 리본은 「새로고침하면 처음 상태로 돌아갑니다」라고 하는데 상태를 `sessionStorage`에 저장해서 새로고침해도 유지됩니다. 「예시 데이터 초기화」를 눌러야 처음으로 돌아갑니다. 탭을 닫으면 사라집니다.
- 영향: 시연 중 이전 조작이 남아 있어 데모가 어긋납니다.
- 제안: 문구를 「탭을 닫거나 '예시 데이터 초기화'를 누르면 처음 상태로 돌아갑니다」로 바꿈.
- 상태: 수정 가능.

**E-61 로그인 오류 문구**
- 무엇이 문제인가: ① 잘못된 비밀번호는 Supabase가 준 메시지(영문일 수 있음)가 그대로 나옵니다. ② `?e=role` 문구는 「운영자 권한」만 말하고 로그인 직후 문구는 「운영자 또는 지역 파트너 권한」이라 서로 다릅니다. ③ 시도 횟수 제한 안내가 없습니다.
- 영향: 운영자가 이유를 못 읽고, 지역 파트너가 자기 계정이 막힌 줄 오해합니다.
- 제안: 한국어 한 문구로 통일(「이메일 또는 비밀번호가 맞지 않습니다」), 역할 문구 통일.
- 상태: 수정 가능. 비밀번호 재설정은 E-12.

**E-62 호텔 취소 안내 등 수동 발송에 의존**
- 무엇이 문제인가: 견적 받는 중에 취소해도 초대한 호텔에는 자동 알림이 없고(OPS_HTL_CANCELLED), 초대 2곳 미만 사전 안내(OPS_ORG_FEW_HOTELS), 미성사 전 확인(OPS_ORG_CLOSE_CHECK), 호텔 중지 안내(OPS_PTN_SUSPEND)도 운영자가 직접 보냅니다. 화면은 안내 문구만 보입니다.
- 영향: 운영자가 잊으면 호텔은 취소된 요청에 견적을 계속 씁니다(링크는 취소 화면으로 바뀌지만 호텔은 이유를 모름).
- 제안: 최소한 OPS_HTL_CANCELLED는 취소 때 자동 발송.
- 상태: **결정 대기**.

**E-63 커미션 카드와 요율 합의를 MVP에 둘지**
- 무엇이 문제인가: 지금 초대는 요율 합의가 끝난 호텔에만 가능합니다. 기존 승인 호텔은 백필하지 않아 모두 「요율 합의 필요」에서 시작합니다(D-40). MVP 검증에서 호텔 3~5곳을 초대하려면 먼저 합의 링크를 모두 돌려야 합니다.
- 영향: 합의가 늦으면 초대 자체가 막힙니다.
- 제안: (a) MVP에서도 둔다 (b) MVP에서는 합의 조건을 끄고 운영자가 수동으로 요율을 기록한다.
- 상태: **결정 대기**(BRIEF §5).

**E-64 대시보드 지표 제목과 서버 값이 다름**
- 무엇이 문제인가: 제목은 「지난달 지표 · {월} · 예시 데이터」로 고정인데, 서버는 이번 달(`now()`)을 계산해 돌려줍니다. api 모드에서도 「예시 데이터」라고 나옵니다.
- 영향: 운영자가 진짜 값을 예시로 오해하거나, 이번 달 값을 지난달로 읽습니다.
- 제안: 월은 서버 값 그대로 쓰고 「예시 데이터」는 mock 모드에서만.
- 상태: 수정 가능.

**E-65 공휴일을 고치면 이미 저장된 기한이 다시 계산되는지 불명 (추정)**
- 무엇이 문제인가: 서버는 요건 확인 시작 때 `sla_due_at`을 저장합니다. 공휴일을 나중에 추가·삭제해도 이미 저장된 기한을 다시 계산하는지는 코드에서 확인하지 못했습니다. 화면은 공휴일 목록으로 기한을 새로 계산하므로 서버 값과 어긋날 수 있습니다.
- 영향: 화면의 SLA 배지와 서버 지표(SLA 준수율)가 다릅니다.
- 제안: 공휴일 변경 때 진행 중 건의 기한을 다시 계산하거나, 화면도 저장된 `sla_due_at`을 그대로 씀.
- 상태: 확인 필요.

**E-66 화면 시각이 페이지를 연 시점에 고정됨**
- 무엇이 문제인가: `A.NOW`가 페이지 열 때 한 번만 정해집니다. 열어 둔 채로는 SLA 배지 · 마감까지 남은 시간 · 「접수 후 미확인」이 바뀌지 않습니다. 마감 저장의 「현재 시각 이후」 검사도 이 값을 씁니다.
- 영향: 오래 열어 둔 화면에서 이미 지난 마감을 저장할 수 있습니다.
- 제안: 1분마다 시각을 갱신하고 배지를 다시 그림.
- 상태: 수정 가능.

**E-67 동시 수정 보호가 없음 (추정)**
- 무엇이 문제인가: 서버는 `row_version`을 올리지만 화면은 보내지 않습니다. 같은 견적 요청을 두 사람이 열면 나중에 저장한 쪽이 이깁니다. 서버가 거절하는지는 확인하지 못했습니다.
- 영향: 특히 공개 메모와 선정 표시가 서로 덮어씁니다.
- 제안: 읽은 `row_version`을 보내고 다르면 STATE_CONFLICT로 새로고침 안내.
- 상태: **결정 대기**(MVP에서 운영자 1~2명이면 보류 가능).

**E-68 설정 화면의 규칙·시스템·전제 조건이 고정 문구**
- 무엇이 문제인가: 기본 규칙 탭의 기한·한도, 시스템 상태의 정기 작업 시각과 시크릿 「미설정」, 전제 조건의 「완료 0 · 화면 제작됨 1 · 미완 11」은 코드에 적힌 문장입니다. api 모드에서도 같습니다. 알림 템플릿 표는 `notification-templates.json`(생성물)과 따로 적혀 있어 자동 29개 · 수동 14개가 어긋날 수 있습니다.
- 영향: 운영자가 시크릿이 모두 미설정이라고 오해하거나 오래된 규칙을 읽습니다.
- 제안: 시스템 상태는 서버 값을 읽어 오거나 탭에서 빼고, 템플릿 표는 JSON에서 생성.
- 상태: **결정 대기**(보조 화면).

**E-69 지역 파트너가 설정·회원 화면을 주소로 열 수 있는지 (추정)**
- 무엇이 문제인가: 메뉴는 역할로 가리지만 `settings.html` · `members.html` 등은 화면 쪽 역할 검사 없이 `A.boot`만 호출합니다. 서버 RPC는 운영자 전용이라 데이터는 안 오지만 빈 화면이나 `MG:FORBIDDEN` 토스트가 보일 수 있습니다.
- 영향: 파트너에게 운영자 메뉴 구조가 드러납니다.
- 제안: `A.boot`에 허용 역할을 넘겨 맞지 않으면 대시보드로 보냄.
- 상태: 확인 필요.

**E-90 콘솔에 불러오는 중 표시가 없음** (2026-10-09 독립 검증에서 추가)
- 무엇이 문제인가: api 모드에서 `A.boot`가 `admin_snapshot()`을 기다리는 동안 본문이 비어 있습니다. 스피너나 「불러오는 중」 문구가 없습니다. 실패하면 `index.html?e=snapshot`으로 돌아갑니다.
- 영향: 데이터가 많아지면 운영자가 화면이 멈춘 줄 압니다.
- 제안: `main`에 「불러오는 중입니다…」를 먼저 그리고, 응답이 오면 바꿈.
- 상태: 수정 가능.
