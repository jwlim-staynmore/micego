## 4. 화면 템플릿 (모든 화면 같은 순서)
```markdown
### ORG-02 진행 상황 화면 `ko/track.html?t=` 〔MVP 핵심〕
**왜 필요한가** 한 줄.
**누가 · 어떻게 들어오나** 진입 경로와 이동 방식.
**나가는 길** 버튼 → 목적지 화면 ID (이동 방식).
**데이터** 서버 응답 필드 / 빌드 때 고정 / 예시값(미연결) 구분.
**Figma** `ORG-02 · {상태}` | **코드 근거** 파일·함수·상수.

① 화면 상태
| 상태(slug) | 화면 이름 | 언제 들어오나 | 보이는 것 | 할 수 있는 일 |

② 요소
| 요소 「화면 문구」 | 왜 있나 | 기본 | 비활성 | 진행 중 | 완료 | 오류 | 누르면 (이동 방식 → 결과) |

③ 상태 전환
| 지금 | 누가·무엇을 (조건) | 다음 | 화면에서 바뀌는 것 | 알림 | 서버 호출 |

④ 숨김·보안 — 이 화면에 절대 나오면 안 되는 정보
⑤ 미결 — **결정 대기** · (추정) · 결함 E-/K- 번호
```
- 이동 방식은 네 가지만: **페이지 이동**(URL 바뀜) / **모달**(화면 위에 뜨고 뒤가 잠김) / **인라인 패널**(같은 화면 안에서 펼침) / **외부 앱**(메일 앱 등).
- 셀이 해당 없으면 "—", 상태가 없는 요소는 해당 칸 "—".
- 〔다음 단계〕 화면은 축약형: 왜 필요한가 + 진입 + ① 화면 상태 + 주요 버튼 3~5개(이동 방식) + ⑤ 미결.

## 5. MVP 태그
- 〔MVP 핵심〕 검증의 두 흐름(견적 요청 접수 → 호텔 견적·비교표·선택)이 이것 없이 끝까지 돌지 않음.
- 〔보조〕 한 달 운영에 필요하지만 손으로 대체할 수 있는 것.
- 〔다음 단계〕 검증 통과 뒤.
- 화면은 태그 하나. 요소마다 다르면 ② 요소 표의 "왜 있나" 끝에 〔다음 단계〕처럼 붙임.
- **결정 대기**(MVP 범위가 아직 안 정해진 것): 선택 인증(SMS)을 MVP에 둘지 / 요율 합의 조건을 MVP에서도 둘지 / 호텔 등록 화면 대신 운영자 수동 등록 / 검증 목표 수치·시작일.
