### CMN-02 개인 링크 공통 상태 (loading / invalid / 미리보기) 〔MVP 핵심〕
**왜 필요한가** 로그인 없이 `?t=` 링크로 여는 화면이 모두 같은 규칙으로 "불러오는 중 → 정상 또는 열 수 없음"을 보여 주도록 맞춘 패턴입니다. 요청자 진행 상황 화면(ORG-02)이 가장 크게 씁니다.
**누가 · 어떻게 들어오나** 메일·알림톡 버튼이 개인 링크(`?t=`) 또는 공유 링크(`?s=`, ORG-02 한정)를 엽니다.
**나가는 길** 이 패턴 자체의 나가는 길은 없고, 각 화면(ORG-02·HTL-03 등)이 이어받습니다. invalid 패널의 「문의하기」는 ORG-09로 페이지 이동합니다.
**데이터** 주소의 `t`(또는 `s`), 선택적으로 `state`; 설정 값 `MG_CONFIG.supabase.url`(있으면 api 모드), `MG_CONFIG.demo`. 서버 값은 화면별 조회 함수(ORG-02는 `get_track`)가 채웁니다.
**Figma** `CMN-02 · loading`, `CMN-02 · invalid`, `CMN-02 · 미리보기 띠` | **코드 근거** `build2.py` `STATE_HEAD`(호텔 견적 페이지·수신 거부 페이지), `STATE_HEAD_SHARE`(ORG-02), `mgLoadTrack()`, CSS `[data-states]{display:none}` + `html[data-state=…]` 규칙.

### CMN-01 의견 보내기 위젯 `assets/feedback.js` 〔보조〕
**왜 필요한가** 요청자·호텔이 화면에서 막힌 일을 그 자리에서 알리고, 운영자가 어느 화면·상태에서 났는지 바로 알 수 있게 합니다.
**누가 · 어떻게 들어오나** 거의 모든 화면 오른쪽 아래 고정 버튼 「의견 보내기」(영어 화면 「Feedback」)나 푸터의 「의견 보내기」 링크. 단 문의 화면(ORG-09·HTL-07)과 피드백 이름의 화면에서는 버튼이 꺼집니다(`data-mgfb-launcher="off"`).

**데이터** 입력값 + 자동 첨부(`ctx`): 페이지 경로(토큰 값 제외), 화면 상태(`MICEGO_PAGE_STATE.state`, 미리보기면 `preview:값`), 요청번호(형식 `MG-YYMM-NNN`일 때만), 개인 링크 종류와 토큰 해시 앞 8자, 브라우저·OS, 화면 크기, 시간대, 빌드 버전, 최근 오류 3건(이메일·토큰·긴 숫자는 가림). IP는 저장하지 않습니다. 제출 주소는 `…/functions/v1/feedback-submit`.

⑤ 미결
- **결정 대기**: 선택 인증(SMS)을 MVP에 둘지. 안 두면 선택은 운영자 대리 확정(이메일 회신 확인 후 동의 기록)만 쓰고, P1~P3 흐름과 ORG_PICK_OTP는 다음 단계로 내립니다. 둘지 정하면 P3/P3' 중 어느 쪽이 기본인지(`pick_auto_close`)도 같이 정합니다.

**코드와 문서의 모순 (코드를 따랐음)**
1. v1 ORG-02: 조회 실패 시 RATE_LIMITED 토스트 → 코드는 모든 오류를 invalid로 처리(E-30).
2. v1 ORG-01a: 회사·담당자명 "수정 가능" → 서버가 프로필 값으로 덮어씀(E-29).
3. v1 ORG-01: 시작일 "오늘 이상"을 클라이언트 검증처럼 적음 → 클라이언트는 값만 확인하고 서버만 오늘 이상을 검사(E-28).
